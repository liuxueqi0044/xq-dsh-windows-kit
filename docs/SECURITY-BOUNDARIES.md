# 安全边界与不可变规则

状态：`ARCHITECTURE-FROZEN`

## 1. 保护对象

- 用户 API Key、Token、Cookie 和登录信息；
- 用户主目录、生产目录、私人仓库与工作区外文件；
- DSH Profile、会话和本地配置；
- 构建时的官方来源真实性；
- 本机网络边界；
- 诊断报告和售后沟通中的隐私；
- 商品品牌与能力声明的真实性。

## 2. 信任区

| 区域 | 信任级别 | 规则 |
|---|---|---|
| XQ 冻结源码与清单 | 高，但必须经测试 | 只能由仓库审查流程变更 |
| 官方 npm/GitHub | 外部可信来源 | 必须 HTTPS、主机白名单、精确版本与 hash |
| DSH 上游运行时 | 外部代码 | 不声明已由 XQ 安全审计 |
| 用户测试工作区 | 有限信任 | 仅允许明确选择的窄目录 |
| DSH Home/Profile | 敏感本地状态 | 诊断只读取最少元数据；变更前备份 |
| 第三方 Skill/插件 | 默认不可信 | 先审核、再确认、后安装；失败回滚 |
| 诊断报告 | 可能敏感 | 两次脱敏、本地保存、用户自行发送 |

## 3. 不可变安全规则

1. 包名必须是 `@deepseek-ai/dsh`，版本必须是 manifest 中的精确版本。
2. npm registry 必须是 `https://registry.npmjs.org/`。
3. Web host 必须是 `127.0.0.1`；不得接受 `0.0.0.0`、`::`、局域网地址或主机名替代。
4. 默认权限必须是 `workspace-write + ask`。
5. 首次运行不得使用用户根、磁盘根、Desktop、Documents 根或 Downloads 根。
6. API Key 只能由用户在 DSH 自身界面输入；XQ 脚本不接受 Key 参数。
7. 检查器和诊断器不得安装、修复、提权、结束进程或改变系统策略。
8. 启动器不得隐藏窗口、后台常驻、建立服务、计划任务或开机启动。
9. 自助 ZIP 不包含插件安装执行器。
10. 未取得 VM 证据时，发布状态不得为 `releasable`。

## 4. 安全工作区判定

公共安全内核必须先规范化路径，再检查：

- 拒绝空路径、相对路径、通配符路径和不存在的 provider；
- 拒绝任何盘符根、UNC 根、用户主目录和 Windows 系统目录；
- 拒绝已知宽目录：Desktop、Documents 根、Downloads 根；
- 拒绝路径中包含无法解析的 reparse point；首次工作区默认拒绝 reparse point/junction/symlink；
- 默认路径为 `%USERPROFILE%\Documents\XQ-DSH-Sandbox`，不是 Documents 本身；
- 已存在目录必须允许枚举顶层元数据，但不得扫描文件内容；
- 非空目录在首次运行时阻断，除非未来另有经过审核的“已有测试工作区”流程；
- 创建目录前必须显示完整规范路径并获得确认。

路径检查只能降低风险，不能宣称形成强隔离。

## 5. 网络边界

运行时允许的网络行为：

- 用户确认后，npm/npx 访问官方 npm registry 下载锁定包及其依赖；
- DSH 按用户配置访问 DeepSeek API；
- 浏览器访问 `http://127.0.0.1:3080`。

XQ 工具禁止：

- 上传诊断或遥测；
- 添加防火墙规则；
- 绑定公网或局域网地址；
- 安装反向代理；
- 把一次性 URL Token 写入日志或客服材料；
- 跟随到未列入信任清单的下载主机。

## 6. 凭据与脱敏

诊断白名单中不得出现完整环境变量。脱敏至少识别：

- `Authorization: Bearer ...`；
- `sk-` 等常见 API Key 形态；
- JWT 三段式 Token；
- URL userinfo 和 query 中的 token/key/secret；
- JSON、YAML、INI、PowerShell 赋值中的 password/token/key/cookie/secret；
- DSH 一次性 URL Token。

第一次脱敏在字段生成时完成，第二次脱敏在序列化文本写盘前完成。二次扫描仍命中测试用敏感模式时必须拒绝写盘。

## 7. 外部命令

- 所有参数使用参数数组，不拼接后交给 `Invoke-Expression`。
- 禁止 `cmd /c` 包装来自用户的路径或包名。
- 不把凭据放入命令行。
- 检查器调用的命令必须是只读版本或状态命令。
- 未验证的 DSH 输出先脱敏再展示或记录。
- 超时必须终止当前检查子进程，但不得终止不属于本工具的系统进程。

## 8. Skill 与插件事务

Skill 安装前需检查名称、frontmatter、路径引用、敏感模式、危险指令、来源和许可证。插件安装前需检查精确版本、tarball、integrity、package scripts、bundle 声明、依赖风险和外部服务。

Profile 变更采用事务：

```text
只读预检 → 备份+hash → 用户确认 → 安装 → dump-config → 启动检查
→ 最小功能验证 → 监听复核 → 成功登记
                          ↘ 任一步失败：回滚并验证备份
```

Git 源、未知 lifecycle script、原生二进制、浏览器驱动、后台服务、OAuth、付费 API 或 `allowBuilds` 均不属于默认 ¥5 服务。

## 9. 制品边界

构建使用文件白名单，不使用“复制仓库全部内容再排除”的方式。ZIP 扫描必须拒绝：

- `.env` 和常见凭据文件；
- npm cache、`node_modules`、tarball 和临时 staging；
- DSH Home、Profile、会话、工作区和日志正文；
- 私钥、证书私钥、浏览器数据；
- 未列入布局清单的可执行文件；
- 外链脚本、iframe、远程字体、统计和广告资源。

## 10. 残余风险

- DSH 仍是开发者预览版，且未完成独立安全审计；
- Windows 沙箱属于部分限制；
- `npx` 的顶层精确版本不等于所有传递依赖完全冻结；
- 第三方插件的静态检查不能证明运行时无恶意行为；
- 脱敏规则不能数学上保证识别所有未知秘密格式；
- 本地 loopback 服务仍可能受到本机恶意软件或浏览器扩展影响。

这些风险必须出现在用户指南和发布审查中。
