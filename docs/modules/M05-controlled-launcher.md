# M05 受控启动器

## 目标

从经确认的窄工作区启动 manifest 锁定的官方 DSH Web UI，保持控制台可见、仅监听 loopback，并向用户说明下载、PID、URL 与停止方式。

## 前置门禁

M02 的 `SUP-014` 必须先确认锁定版本的准确 Web host/port 参数和默认监听行为；`SUP-015` 必须确认 `workspace-write + ask` 的真实配置及验证方式。没有证据时本模块保持阻塞，不得猜测命令行或配置字段。

## 输入

- `-WorkspacePath`；
- `-WhatIf`：只显示计划，不下载、不创建、不运行；
- 商品随包 manifest；
- M03 公共模块和 M04 环境结果。

v1 不提供 host、port、sandbox、approval、package 或 registry 覆盖参数，也不提供绕过确认的 `-Force`/无人值守模式。

## 依赖与非职责

依赖 M01、M03、M04 以及 M02 的 CLI/权限证据。启动器不配置 API Key，不安装 Node，不修改 ExecutionPolicy，不承担插件安装，也不把 XQ manifest 的安全字段当成 DSH 实际配置已经生效的证据。

## 流程

1. 校验 manifest 与运行安全字段；
2. 检查 Node/npm/npx 和端口；
3. 规范化工作区，拒绝宽目录、reparse point 和非空首次目录；
4. 显示将发生的目录创建、官方 registry 访问、精确包与完整参数；
5. 用户明确输入确认；
6. 查询官方精确版本元数据并与 manifest 比较，漂移时停止；
7. 必要时创建唯一窄目录；
8. 按 M02 证据生成或验证 DSH 的 `workspace-write + ask` resolved config；
9. 从工作区启动可见 DSH 进程；
10. 在有限时间内核对 PID、端口和实际监听地址；
11. 显示 `http://127.0.0.1:3080` 与正常停止方法；
12. 传播并解释退出码。

若监听地址不是 loopback，必须报严重错误并要求用户停止；不得静默继续。自动终止策略若要加入，必须另行设计用户确认和进程所有权验证，禁止 `taskkill /F`。

## 进程模型

实现需选择“当前可见控制台直连”或“新建可见 PowerShell 控制台”。无论哪种方式，都必须能识别本次创建的进程、不得隐藏窗口、不得注册常驻项。进程控制 spike 由 Sol 审核后冻结。

## 失败模式

manifest、环境、路径、上游元数据、resolved config、端口或监听任一失败都在启动前或最早可检测点停止。若 DSH 已启动后发现监听不安全，必须显示最高级别警告和明确停止步骤，不得把会话报告为成功。

## 验收标准

- `RUN-001`：只运行 manifest 中的精确 package@version。
- `RUN-002`：浮动版本、非官方 registry 或被篡改 manifest 被拒绝。
- `RUN-003`：首次下载和创建目录前显示行为并确认。
- `RUN-004`：`-WhatIf` 零写入、零下载、零启动。
- `RUN-005`：宽目录、根目录、非空首次目录和 reparse point 被阻断。
- `RUN-006`：实际工作目录等于已确认工作区。
- `RUN-007`：实际监听只有 `127.0.0.1:3080`。
- `RUN-008`：危险 sandbox/approval 配置被拒绝。
- `RUN-009`：控制台可见，显示 PID、URL 和停止方法。
- `RUN-010`：不创建服务、计划任务、开机启动、防火墙规则或后台常驻。
- `RUN-011`：端口占用、网络失败、npm 失败和 DSH boot failure 有友好错误及非零退出码。
- `RUN-012`：用户取消确认时零写入、零下载、零启动。
- `RUN-013`：命令参数使用数组，不存在路径或包名命令注入。
- `RUN-014`：日志和错误不包含 API Key、URL Token 或完整环境变量。
- `RUN-015`：M02 未完成 CLI 参数证据时，本模块不能标记完成。
- `RUN-016`：M02 未完成权限配置证据或 resolved config 不符合时，本模块不能启动。
