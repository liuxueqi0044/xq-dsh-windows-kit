# M06 只读诊断与二次脱敏

## 目标

收集解决常见启动问题所需的最少元数据，生成本地 JSON 报告，同时避免读取或泄露凭据、会话和工作区内容。

## 输入

- `-WorkspacePath`：仅检查路径宽度和元数据；
- `-OutputPath`：用户明确指定本地文件；
- `-Profile web`：固定支持的 Profile；
- M01 manifest 与 M03 公共模块。

## 依赖与非职责

依赖 M01、M03 和 M02 对 dump-config 副作用的证据。它不进行修复、安装、Profile 初始化、日志上传或工作区内容调查。

## 允许采集

- Windows、架构、Node/npm/npx/pnpm/DSH 版本；
- 3080 监听地址、PID 和 DSH 进程存在性；
- DSH Home/Profile 是否存在；
- Profile package.json 中插件包名与精确版本；
- Skill 名称和来源目录；
- dump-config 仅记录成功、退出码和脱敏错误摘要；
- 工作区路径风险分类；
- XQ 启动器自身保存的脱敏退出摘要（若存在）。

## 禁止采集

完整环境变量、API Key、Token、Cookie、Profile 凭据内容、dump-config 正文、会话正文、工作区文件名/内容、浏览器历史、私人仓库信息和付款身份。

## dump-config 约束

只有 M02 证明该操作在现有 Profile 上不会初始化或写入，且目标 Profile 已存在时才执行。否则记录 `NOT_RUN` 和原因。输出正文永不写入报告。

## 报告管线

1. 白名单字段采集；
2. 每个外部字符串字段立即脱敏；
3. 形成内存对象；
4. JSON 序列化到内存；
5. 全文二次脱敏；
6. 敏感 canary 扫描；
7. 以新文件方式写盘，不覆盖现有文件，除非用户另行确认。

## 失败模式

任何探针失败只记录脱敏状态和错误代码；二次脱敏、敏感扫描、Schema 或原子写入失败时整体拒绝写盘。不得保留临时明文文件。

## 验收标准

- `DIA-001`：报告只包含 Schema 白名单字段。
- `DIA-002`：不枚举或输出完整环境变量。
- `DIA-003`：不读取会话或工作区内容。
- `DIA-004`：只列 Skill 名称与来源目录，不读取 SKILL.md 正文。
- `DIA-005`：插件只列包名与版本，不收集配置值。
- `DIA-006`：dump-config 正文不进入内存报告或磁盘。
- `DIA-007`：Profile 缺失时不运行可能初始化的命令。
- `DIA-008`：字段级和序列化后两次脱敏均执行。
- `DIA-009`：包含假 Key/JWT/Cookie/URL Token 的夹具中零明文泄漏。
- `DIA-010`：工具不联网、不上传、不自动修复。
- `DIA-011`：写盘失败或二次扫描失败时不留下半成品报告。
- `DIA-012`：默认不覆盖既有报告。
- `DIA-013`：报告自身记录工具版本、时间、Schema 版本和脱敏版本。
- `DIA-014`：售后所需报告可由用户打开检查后自行发送。
- `DIA-015`：最近启动错误只来自 XQ 自身的脱敏摘要，不读取上游会话或任意日志正文。
