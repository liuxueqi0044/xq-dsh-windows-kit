# M10 自动化测试与 CI

## 目标

把安全规则和发布前置条件转化为可重复执行的测试，确保失败场景是真正的失败，而不是警告或跳过。

## 输入、依赖与非职责

依赖所有被测模块的公开合同。M10 负责编排“预构建测试 → M09 构建 → 制品测试”，不修改生产策略、不自动签署人工门禁，也不把网络暂时不可用改成成功。

## 测试层级

1. 单元测试：M03 纯函数、Schema、脱敏和路径判定；
2. 契约测试：各脚本参数、输出对象、退出码和 manifest 接口；
3. 负向安全测试：篡改包、host、权限、工作区、HTML、Skill、插件；
4. 制品测试：目录、白名单、敏感扫描、hash 和可重复构建；
5. 网络供应链测试：官方 registry/GitHub 观察与冻结值比较；
6. Windows 集成测试：进程、端口、PowerShell 5.1；
7. M11 人工 E2E：不由 CI 假装完成。

## 工具与工作流

- Pester 版本在 CI 中精确锁定；
- `tests/Invoke-Tests.ps1` 统一分组；
- `validate.yml` 在 push/PR 到 main 运行静态、单元、契约和制品预检；
- `build-candidate.yml` 手动或受保护触发，执行在线供应链验证和候选构建；
- 跳过的必需测试视为失败；网络测试只有在明确的候选工作流中运行。

测试夹具只能使用明显虚假的秘密，例如 `sk-test-DO-NOT-USE-*`，并由构建规则确保夹具不进入 ZIP。

## 失败模式

断言失败、必需测试跳过、测试进程崩溃、超时或结果文件缺失均使工作流失败。候选网络测试失败可重试但不能降级为警告；重试次数和最终原因需记录。

## 验收标准

- `TST-001`：任务书列出的每个自动化场景至少映射一个测试。
- `TST-002`：浮动版本、非官方 registry、错误包名和 alpha 未批准被拒绝。
- `TST-003`：错误 SRI/SHA/commit/LICENSE 被拒绝。
- `TST-004`：非 loopback 和危险默认权限被拒绝。
- `TST-005`：宽工作区和路径逃逸被拒绝。
- `TST-006`：HTML 外链、远程脚本和统计被拒绝。
- `TST-007`：敏感 ZIP 夹具被拒绝。
- `TST-008`：诊断脱敏 canary 零泄漏。
- `TST-009`：DSH 缺失、端口占用、网络失败有预期非零退出。
- `TST-010`：Skill 非法名称、frontmatter 和路径逃逸被拒绝。
- `TST-011`：插件浮动版本、未知脚本和 allowBuilds 被分类为不合格。
- `TST-012`：Profile 备份、失败回滚和删除流程有集成测试。
- `TST-013`：Windows PowerShell 5.1 和 PowerShell 7 均运行核心测试。
- `TST-014`：必需测试为 skipped/pending 时工作流失败。
- `TST-015`：main 上实际绿色 run 的 URL/ID 被记录，不能用本地结果替代。
- `TST-016`：测试不得通过修改生产安全默认值来获得绿色。
